How it works

From a task to a result you can review.

01

Set the direction.

Describe what you need, by text or voice. Attach files. Ask for a plan first, and let the agent start once you approve it.

02

Let the agent work.

Each coding session gets its own branch and working copy. Run several in parallel and keep subscription usage in view.

03

Stay involved where it matters.

Answer questions, approve protected access, and review the result. Pull requests show their review and CI status.

Control

Control the four things that matter.

Keep your knowledge on your server.

Documents, meeting transcripts, and findings live with your project and persist when a sandbox is replaced. Record meetings on iPhone or iPad. Share selected knowledge across projects.

Choose the model for the work.

Use Claude Code, Codex, or open-source models through OpenCode. Switch per session. Your knowledge and history stay in Verity.

Give agents access. Keep the keys.

A broker holds credentials and runs approved operations. Agents use project secrets without seeing their values. You approve protected access once, for the session, or for 30 days in the project.

Run agents inside clear boundaries.

Every project runs in its own container, isolated with gVisor. Verity offers a three-day release delay for new packages from npm, pnpm, Yarn, Bun, pip, and uv. Agent pushes pass a secret scan and a code review.

Anywhere

Start at your desk. Continue from your pocket.

Sessions run on your server, so you pick them up from any device. Verity shows which session needs your attention and what each agent is doing.

  • Automations run a session daily, weekly, or on an interval.
  • Tasks carry agreed work across sessions.
  • Parallel sessions work on different projects at once.
  • Voice input and attachments on every device.
Scope

What Verity is not.

Not an editor

No completion and no inline editing. Agents work on your repositories and your Git workflow.

Not a hosted service

It runs on your Linux server under the Apache License 2.0. Online meeting bots and sharing previews outside your network use the separate Verity Premium service.

Not a privacy shield for inference

Context sent to an external model is processed by that provider. Your knowledge and sessions stay on your server.

Not a credential guarantee for every path

Claude Code and Codex credentials stay outside project sandboxes. OpenCode has its own boundaries, described in the security model.

Not a safety certificate

Sandboxes and release delays reduce risk. They do not certify code or packages as safe. The release delay is optional.

Not finished

Verity is in beta. Features and setup may change as testing progresses.

Put your agents to work on your terms.

You need a Linux server with Docker that stays on, and a Claude or ChatGPT subscription or an OpenAI-compatible API key. Verity installs as one package with PostgreSQL included. The getting started guide takes you from an empty server to your first session in about 30 minutes.
