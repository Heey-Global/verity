How it works

From a task to a merged pull request.

Describe the work, by text or voice. Verity gives every session its own branch and working copy, and brings you in where your judgement counts.

01

Plan first, if you like.

The agent proposes the steps. Nothing changes until you choose Implement.

02

Run sessions in parallel.

Each session works on its own branch, across projects and models. You see which one needs you.

03

Review and merge.

The agent opens a pull request. Verity shows its CI checks and lets you merge once they pass.

Approvals

Nothing leaves without your OK.

Agents prepare the migration, the deploy, the email to your team. You see exactly what will run or go out, and decide with one tap on whichever device is closest.

  • See exactly what happens.The command, the recipient, the full text, before anything runs.
  • Decide from any device.The request waits in the browser, on iPad, and on iPhone.
  • Choose how long it holds.Once, for the session, or for 30 days in the project.

Security

Clear boundaries for every agent.

Agents run code, install packages, and push branches. Verity keeps that work inside a sandbox and the keys outside of it.

  • One sandbox per projectIts own container, isolated with gVisor.
  • No keys in the sandboxA broker holds credentials and runs approved operations.
  • A three-day release delayOffered on the first install for npm, pnpm, Yarn, Bun, pip, and uv.
  • Checked before every pushA secret scan and a code review run first.

Scope

What Verity is not.

Not an editor

No completion and no inline editing. Agents work on your repositories and your Git workflow.

Not a hosted service

It runs on your Linux server under the Apache License 2.0. Online meeting bots and sharing previews outside your network use the separate Verity Premium service.

Not a privacy shield for inference

Context sent to an external model is processed by that provider. Your knowledge and sessions stay on your server.

Not a credential guarantee for every path

Claude Code and Codex credentials stay outside project sandboxes. OpenCode has its own boundaries, described in the security model.

Not a safety certificate

Sandboxes and release delays reduce risk. They do not certify code or packages as safe. The release delay is optional.

Not finished

Verity is in beta. Features and setup may change as testing progresses.

Put your agents to work. On your terms.

You need a Linux server with Docker that stays on, and a Claude or ChatGPT subscription or an OpenAI-compatible API key. Verity installs as one package with PostgreSQL included. The getting started guide takes you from an empty server to your first session in about 30 minutes.
